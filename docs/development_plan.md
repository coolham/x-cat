## 主运行框架设计

### 架构概述

系统采用模块化、插件式架构，主要由以下部分组成：

1. **核心运行时（Core Runtime）**
   - 模块注册表
   - 生命周期管理器
   - 配置管理器
   - 事件总线
   - 调度器

2. **模块接口（Module Interface）**
   - 标准化模块接口
   - 模块通信协议
   - 资源访问抽象

3. **功能模块（Functional Modules）**
   - 数据源适配器（Telegram、Discord、RSS等）
   - 内容处理器
   - 分析器（GPT分析器等）
   - 存储后端
   - 用户界面

### 模块生命周期

每个模块遵循以下生命周期：

1. **注册**：模块向核心运行时注册自身
2. **初始化**：加载配置，准备资源
3. **启动**：开始工作，处理事件
4. **暂停/恢复**：可以临时暂停和恢复
5. **停止**：清理资源，准备关闭
6. **注销**：从核心运行时移除

### 模块间通信

模块间通信通过以下机制实现：

1. **事件总线**：发布-订阅模式，模块可发布事件并订阅感兴趣的事件
2. **直接调用**：通过接口直接调用其他模块的方法
3. **消息队列**：用于异步处理和解耦

### 配置管理

系统配置分为多个层次：

1. **全局配置**：影响整个系统的设置
2. **模块配置**：特定模块的设置
3. **运行时配置**：可在运行时动态调整的设置

配置支持从多种源加载：文件、环境变量、命令行参数、远程配置服务等。

## AI分析功能实现

AI分析功能目前已完成基础框架的开发，支持多种AI服务提供商：

1. **统一API接口**: 
   - 通过`AIClient`类提供标准化的API接口
   - 支持异步分析请求，适应大量消息处理需求

2. **多提供商支持**:
   - 支持OpenAI API
   - 支持OpenRouter（可接入多种模型）
   - 支持DeepSeek

3. **代理服务器支持**:
   - 通过环境变量配置代理
   - 支持HTTP/HTTPS代理
   - 针对不同提供商的特定代理控制

4. **内容处理**:
   - 网页内容提取
   - URL识别和提取
   - 内容长度控制，适应不同模型的上下文限制

5. **错误处理**:
   - 异常捕获和日志记录
   - 响应格式化和规范化
   - JSON解析与验证

后续计划增强AI分析的深度和广度，包括更多模型支持、更复杂的分析任务以及结果优化。
