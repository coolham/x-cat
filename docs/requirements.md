# X帖子自动分类与存储系统需求文档

## 引言

本需求文档描述了一个自动分类和总结 X 帖子并存储到内容管理工具的系统，旨在指导开发人员实现用户的需求。该系统通过中间应用（如 Telegram）转发内容，使用 AI 进行分类和总结，最后存储到 Notion 或类似工具（如 Airtable）。文档包括系统场景和功能需求，不涉及具体实现方案。

## 设计原则

本项目作为个人信息助理的基础架构，需要遵循以下设计原则：

### 1. 模块化设计
- **接口分离原则**：各功能模块通过标准接口通信，降低耦合度
- **单一职责**：每个模块只负责一个特定的功能领域
- **可替换性**：模块之间可以独立升级或替换，不影响整体系统
- **标准化接口**：定义清晰的模块间通信协议和数据格式

### 2. 扩展性设计
- **插件化架构**：支持通过插件方式扩展系统功能
- **适配器模式**：使用适配器隔离第三方服务，便于更换或升级
- **配置驱动**：核心功能通过配置文件控制，避免硬编码
- **开放集成**：预留与其他系统集成的接口和扩展点

### 3. 可维护性
- **代码规范**：遵循行业最佳实践和设计模式
- **文档完备**：维护详细的API文档和开发指南
- **测试覆盖**：完整的单元测试和集成测试
- **监控告警**：系统运行状态的监控和异常处理机制

### 4. 未来扩展方向
- **多源输入**：支持更多内容来源（如RSS、邮件、其他社交媒体）
- **智能处理**：增强AI处理能力（如情感分析、关键词提取）
- **数据分析**：添加数据统计和可视化功能
- **自动化工作流**：支持用户自定义的处理流程
- **协作功能**：支持多用户协作和内容共享

## 系统场景

用户每天需要阅读大量 X 帖子，其中包含有价值的信息需要收藏。用户关注的信息种类多样，包括 AI、Python、电子设计、数字货币等。为提高效率，用户希望设计一个系统，自动处理这些 X 帖子，流程如下：

1. **手动转发**：用户将选定的 X 帖子手动转发到中间应用的通用频道（如 Telegram 的"general"频道）。
2. **AI 处理**：系统通过 API 读取通用频道中的内容，使用 AI 工具对帖子进行分类和总结。
3. **分类转移**：根据 AI 的分类结果，将帖子转移到中间应用的分类频道（如"AI"、"Python"等）。
4. **存储管理**：将分类后的信息（包括类别、总结、原始文本和 X 帖子链接）存储到内容管理工具（如 Notion 或 Airtable），便于后续检索和组织。

用户希望系统支持多样化兴趣的分类，确保分类准确，并提供用户审核机制以修正 AI 的结果。系统需考虑成本、隐私和扩展性，适合个人或小团队使用。

## 功能需求

### 1. 中间应用支持

#### 功能：
- 支持用户手动将 X 帖子转发到中间应用的通用频道
- 通用频道需能接收文本、链接和可能的附件（如图片）
- 系统需支持从通用频道读取新消息，并根据分类结果将消息转移到分类频道

#### 需求：
- 中间应用需提供 API，支持机器人读取和转发消息
- 机器人需有权限访问通用频道和所有分类频道
- 消息转移需保留原始消息的上下文（如发送者信息、时间戳和附件）
- 设计标准化的消息处理接口，支持未来接入其他消息源
- 实现消息源适配器接口，确保不同消息源的一致性处理

#### 用户体验：
- 用户应能轻松设置通用频道和分类频道
- 机器人应能处理每日数百条消息，性能稳定

### 2. AI 分类和总结

#### 功能：
- 系统使用 AI 工具对通用频道中的新消息进行内容分析、分类和总结
- 分析过程需分为预处理和深度分析两个阶段
- 预处理阶段识别消息内容和提取URL链接
- 深度分析阶段需对消息内容和相关网页内容进行综合分析
- 分类需支持至少二级分类体系，便于构建个人知识库
- 总结需生成可配置长度（默认100字左右）的要点概述，捕捉内容核心信息

#### 需求：
- AI预处理模块：
  - 识别消息中的文本内容、链接、媒体类型等
  - 提取消息中的URL链接，并进行基本验证
  - 确定消息的初步分析价值，过滤无效内容

- 网页内容获取模块：
  - 支持访问消息中提取的URL链接
  - 必须支持通过代理服务器访问网页内容（可配置）
  - 支持网页正文提取，剔除无关内容（如广告、导航栏等）
  - 支持不同类型的网页内容处理（文章、视频页面、社交媒体等）
  - 处理网页访问的异常情况（超时、拒绝访问等）

- 内容组装模块：
  - 将原始消息和提取的网页内容组合为统一格式（如Markdown）
  - 确保组装的内容结构清晰，便于AI进行分析
  - 解决潜在的编码、特殊字符等问题
  - 控制组装内容的长度，确保不超过AI处理能力

- AI分析模块：
  - 支持多级分类系统（至少二级分类）
  - 分类体系需满足个人知识库构建的需求
  - 提供长度可配置的内容摘要（默认100字左右）
  - 提取关键概念和实体
  - 生成结构化的分析结果，便于存储和检索

- AI 工具需支持零样本分类，无需额外训练
- 输出格式需结构化（如 JSON），包括分类、摘要、关键实体等
- 设计可扩展的AI处理管道，支持添加新的处理模型
- 实现模型适配器接口，支持多种AI服务提供商

#### 用户体验：
- 分类和总结应准确，便于构建个人知识库
- 允许用户审核和修正分析结果
- 提供分析过程的可视化展示
- 系统需记录 AI 处理的错误，提示用户调整
- 优化处理时间，确保分析结果及时产生

### 3. 分类频道管理

#### 功能：
- 根据 AI 分类结果，将原始消息从通用频道转移到对应的分类频道
- 每个类别对应一个分类频道（如"AI"频道存储所有 AI 相关帖子）

#### 需求：
- 转移过程需保留原始消息的完整性，包括文本、链接和附件
- 系统需支持动态创建或扩展分类频道，适应新类别
- 确保分类频道私有，仅用户和机器人可访问

#### 用户体验：
- 用户应能通过分类频道查看分类结果，验证准确性
- 转移过程应高效，不影响其他频道的使用

### 4. 内容管理工具存储

#### 功能：
- 将分类后的信息存储到内容管理工具，包括类别、总结、原始文本和 X 帖子链接
- 支持用户检索和组织存储的数据

#### 需求：
- 内容管理工具需提供 API，支持创建和更新记录
- 存储格式需结构化，支持字段如类别、总结、原始文本和链接
- 系统需处理每日数百条记录，性能稳定
- 设计统一的存储接口，支持多种存储后端
- 实现数据迁移和备份机制

#### 用户体验：
- 用户应能通过过滤器或视图快速查找特定类别的内容
- 支持用户添加备注或修正字段，记录审核结果

### 5. 系统扩展与用户交互

#### 功能：
- 系统需支持定期检查新消息，处理批量数据
- 提供用户审核机制，允许修正分类和总结

#### 需求：
- 系统需记录已处理消息 ID，避免重复处理
- 支持错误处理，如 API 调用失败或 AI 分类错误
- 提供日志记录，方便用户调试和优化

#### 用户体验：
- 用户可通过内容管理工具查看处理进度和错误日志
- 系统应提示成本（如 AI API 使用费用），帮助用户管理预算

### 6. 内容分析器模块

#### 功能：
- 完成了多AI提供商支持（OpenRouter、DeepSeek）
- 实现了内容类型识别系统，支持纯文本、带URL文本和纯URL分析
- 开发了网页内容提取功能，支持代理访问和内容清理
- 实现了内容组装功能，将原始消息和网页内容组合为统一分析格式
- 完成了AI深度分析功能，包括多级分类、情感分析、关键词提取和摘要生成
- 集成了事件驱动的消息处理和分析结果存储机制

#### 需求：
- 实现内容分析器模块，支持多AI提供商的集成
- 确保分析结果的准确性和可靠性
- 设计可扩展的分析管道，支持添加新的分析模型
- 实现模型适配器接口，支持多种AI服务提供商

#### 用户体验：
- 系统应能处理不同类型的内容分析需求
- 提供分析结果的可视化展示
- 系统需记录分析过程中的错误，提示用户调整
- 优化分析时间，确保分析结果及时产生

## 推荐与考虑

### 技术架构
- **后端框架**：选择成熟的企业级框架，支持模块化和扩展
- **数据存储**：使用可扩展的数据库系统，支持水平扩展
- **消息队列**：引入消息队列处理异步任务，提高系统可靠性
- **API网关**：统一管理服务接口，支持认证和限流
- **容器化部署**：使用容器技术便于部署和扩展

### 开发规范
- **代码风格**：遵循语言社区推荐的代码规范
- **版本控制**：使用Git管理代码，遵循规范的分支策略
- **CI/CD**：建立自动化的构建、测试和部署流程
- **文档管理**：维护API文档、架构文档和使用手册

### 工具选择
- **中间应用**：建议使用 Telegram，因其转发功能保留上下文，适合分类转移
- **AI 工具**：
  - 推荐使用第三方AI API封装库 ai-api-wrapper，支持以下特性：
    - 多种AI供应商统一接口(OpenAI、Anthropic、Microsoft Azure等)
    - 支持配置代理服务器，适合各地区使用
    - 提供统一的异常处理和重试机制
  - 优先使用 GPT-4 模型，支持零样本分类和总结
  - 考虑备选模型如Claude或国内可用模型，提高系统可用性
- **内容管理工具**：
  - Notion
  - Airtable（适合结构化数据）
  - Evernote（笔记组织）
  - OneNote（团队协作）
  - Confluence（知识库）
  - Google Docs/Drive（灵活管理）
  - Trello（看板式组织）

### 其他考虑因素
- **隐私与安全**：确保中间应用和内容管理工具的私有设置，保护用户数据
- **扩展性**：系统需设计为可扩展，支持未来增加类别或处理更多消息

## 智能分类系统需求

### 1. 技术领域分类功能

#### 功能：
- 系统对收集的内容进行智能分类，支持一级分类和二级分类
- 分类体系侧重技术领域，包括但不限于AI、软件工具、电子技术、商务科技等
- 分类结果准确，能够捕捉内容的核心主题和细分领域
- 支持分类体系的动态演化，随着内容增长自适应调整

#### 需求：
- 基础分类框架：
  - 预定义主要一级分类类别，覆盖核心技术领域
  - 为每个一级分类提供初始二级分类示例
  - 在AI领域提供更细致的二级分类，如深度学习、自然语言处理、计算机视觉等
  - 支持分类的层级结构和关系表达

- 分类实现方式：
  - 结合零样本学习和示例引导的分类机制
  - AI能够根据内容特征自动选择最合适的分类
  - 对于新兴或边缘内容，提供创建新二级分类的建议
  - 输出分类置信度，便于判断分类质量

- 分类演化机制：
  - 定期分析分类结果分布，发现分类体系不足
  - 支持用户审核和修正AI分类结果
  - 基于一定数量的内容积累，自动提出分类体系优化建议
  - 保留分类版本历史，支持历史内容重新分类

- 分类数据存储：
  - 存储分类元数据，支持分类体系演化记录
  - 存储内容与分类的关联关系
  - 优化分类查询性能，支持基于分类的快速检索

#### 用户体验：
- 用户应能查看所有可用分类及其定义
- 分类结果应直观清晰，便于用户管理内容
- 支持用户对分类结果进行修正和反馈
- 分类体系调整应尽量保持向后兼容，避免频繁重分类
- 系统能够根据用户的分类修正行为学习并改进分类准确性
